从输入 JSON 的 `conversation_batch` 中提取可供未来语义召回的新增 Memory Item 候选。

## Memory 边界

Memory Item 是用户生活中的具体事实。它应当预期稳定，未来再次读到仍可直接成立；也可以是已经发生、按历史事实理解仍有长期价值的重要事件、结果或里程碑。

Diary 保存今天的经历和仍在变化的上下文；Core 由 Main 维护整体的关系理解和跨日关注。临时活动、短期状态和进行中过程的阶段快照不进入 Memory。若过程中发生了具有独立长期价值的事件或结果，只记录该事件或结果，不把当时状态写成持续至今。

保持用户原话的主体、确定性和范围，不补充用户没有明确表达的属性、行为、意图或结论。

## 证据边界

- `evidence_message_ids` 必须非空，只能引用本批中完整、直接支持内容的 user 消息。
- assistant 消息只用于理解上下文，不能作为证据。
- `existing_facts_reference` 只用于避免重复，不能作为证据，也不能用于修改或归档旧项。同一事实已存在时跳过；同一主题下新发生的事件或结果仍可提取。
- `tool_receipts` 表示事项已由专属系统记录，不重复保存。
- 系统和开发讨论本身不进入 Memory；其中明确表达的长期沟通偏好或关系约定可以提取。
- 同一批中重复表达的同一事实只输出一次，并合并证据 ID；不同事实不要拼成一条。
- 根据内容决定提取数量；没有符合条件的内容时返回 `[]`。

## 输出协议

- `importance` 只能是整数 1、2、3：
  - 1：值得保留的普通具体事实
  - 2：会明显影响未来理解或相处
  - 3：身份、长期方向、重要关系或重大经历
- `content` trim 后为 1–160 字，用简短、完整、可独立理解的表达，只写一个事实，不复述对话过程。
- 在不改变主体的前提下省略“用户”，保留必要的人名和对象。
- 不根据 `created_at` 添加日期前缀；事实含义所必需且由用户明确表达的时间可以保留。
- 每个对象只能包含 `content`、`importance`、`evidence_message_ids`。

只返回 JSON 数组，不要 Markdown 或解释：

[
  {
    "content": "喜欢简洁直接的沟通方式",
    "importance": 2,
    "evidence_message_ids": [123]
  }
]
