从输入 JSON 的 `conversation_batch` 中提取可供未来召回的记忆候选。

## 三层边界

- **核心记忆 (`kind=core`)**：跨日仍成立的具体事实、偏好、习惯、关系认识、已发生的重要事件/里程碑。未来再读仍可直接成立。
- **临时记忆 (`kind=temp`)**：只在今天成立、跨日大概率失效的短条目（今天去哪、今晚要交的作业、一时情绪）。不要写进核心记忆。
- **日记**：当天叙事正文由 Main 的 `write_diary` 维护，本抽取不写日记。

Core 由 Main 维护整体关系理解；本抽取只产出短条目。保持用户原话的主体、确定性和范围，不补充用户没有明确表达的属性、行为、意图或结论。

## 标签（必填）

每条必须带至少一个标签，可多选。取值只能是：
`事实` / `情感` / `偏好` / `事件` / `习惯` / `关系`

## 证据边界

- `evidence_message_ids` 必须非空，只能引用本批中完整、直接支持内容的 user 消息。
- assistant 消息只用于理解上下文，不能作为证据。
- `existing_facts_reference` 只用于避免重复，不能作为证据，也不能用于修改或归档旧项。同一事实已存在时跳过；同一主题下新发生的事件或结果仍可提取。
- `tool_receipts` 表示事项已由专属系统记录，不重复保存。
- 系统和开发讨论本身不进入记忆；其中明确表达的长期沟通偏好或关系约定可以提取为 core。
- 同一批中重复表达的同一事实只输出一次，并合并证据 ID；不同事实不要拼成一条。
- 根据内容决定提取数量；没有符合条件的内容时返回 `[]`。

## 输出协议

- `kind` 只能是 `core` 或 `temp`。
- `importance` 只能是整数 1、2、3：
  - 1：值得保留的普通具体事实
  - 2：会明显影响未来理解或相处
  - 3：身份、长期方向、重要关系或重大经历
- `content` trim 后为 1–160 字，用简短、完整、可独立理解的表达，只写一个事实，不复述对话过程。
- `tags` 为非空数组，元素只能是上述六个中文标签。
- 在不改变主体的前提下省略“用户”，保留必要的人名和对象。
- 不根据 `created_at` 添加日期前缀；事实含义所必需且由用户明确表达的时间可以保留。
- 每个对象只能包含 `kind`、`content`、`importance`、`tags`、`evidence_message_ids`。

只返回 JSON 数组，不要 Markdown 或解释：

[
  {
    "kind": "core",
    "content": "喜欢简洁直接的沟通方式",
    "importance": 2,
    "tags": ["偏好"],
    "evidence_message_ids": [123]
  },
  {
    "kind": "temp",
    "content": "今晚要交设计作业",
    "importance": 1,
    "tags": ["事件"],
    "evidence_message_ids": [124]
  }
]
